- 第1回（素のLLM）とエージェントの回答の違い：
  - 第1回の提出記録（[lec01 の解答](https://github.com/thousandplsme/lecture-ai-engineering-2026/blob/lec01/lectures/01/answer.md)）では、素のLLMは「基礎・応用・発展」という一般的な区分を説明したり、講座の情報を持っていないと断って複数の解釈を示したりしていた。
  - 今回、同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか？」に対して、エージェントは用語集を検索し、「基礎・実装・発展」の区分と「どれか1つに取り組めば完了」という講座固有のルールを回答した。末尾には第1回が示された。検索できる情報源を持つことで、講座の定義に沿った回答を得られた（[実測ログ](results/homework_levels.txt)）。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 3レベルの質問：`search_glossary({'query': '3レベル'})`。
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})`。用語を1つずつ検索していた（[変更前ログ](results/before.txt)）。
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})`（[確認問題ログ](results/quiz.txt)）。
- 1つの質問でのLLM呼び出し回数（`requests`）：
  - 3レベルの質問：`requests=2, tool_calls=1`。
  - LoRAとQLoRAの比較（宿題の指示変更前）：`requests=2, tool_calls=2`。
  - 第2回の確認問題：`requests=2, tool_calls=1`。
  - ツールを2つ呼んでもLLM呼び出しが2回で済む場合があり、ツールの呼び出し回数とLLMの呼び出し回数は一致しない。
- 追加したツールと、docstringに書いた説明：
  - `make_quiz(lecture: int) -> str` を追加し、`agent.tool_plain(tools.make_quiz)` で登録した。
  - docstringには「指定した回の用語から1つを選び、確認問題と答えを返す」「『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う」と記載した。
  - 用語集から指定回の用語を集め、`random.choice` で1つ選び、問題と定義をJSON文字列で返す。該当する用語がない回は説明メッセージを返す。
  - `--list-tools` で3つのツールと説明文を確認した（[一覧](results/tools.txt)）。確認問題の実行では「ファインチューニング」の問題が出され、答えはすぐに表示されず、考えるよう促された。
- テスト：`uv run pytest -q` は `11 passed in 6.37s`（[ログ](results/tests.txt)）。これはAPIを呼ばないテストであり、実モデルの回答・ツール選択は上記の実測ログで別に確認した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - `app/agent.py` の `INSTRUCTIONS` の1行だけを変更し、同じ質問「LoRAとQLoRAの違いは？」を `--trace` 付きで実行して比較した。
  - 変更前：`回答の最後に、関係する回（第N回）を示す。`
  - 変更後：`回答の最後に、関係する回（第N回）を示し、理解を確かめる確認問題を1問出す。`
  - モデルは両方とも `gemini-3.5-flash-lite`。ツールの実装・登録・docstringおよび質問は同じにし、各実行は会話履歴を渡さない独立した実行とした。`make_quiz` は比較前から登録済みで、比較中には追加していない。temperatureなどの生成設定は指定していない。
- 結果：
  - 変更前（[before.txt](results/before.txt)）：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。`requests=2, tool_calls=2`。LoRAとQLoRAの違いを説明し、末尾は「第2回」で終わり、確認問題はなかった。
  - 変更後（[after.txt](results/after.txt)）：同じ2つの検索に加えて `make_quiz({'lecture': 2})` が呼ばれた。`requests=3, tool_calls=3`。違いの説明と「関連する回：第2回」の後に、「LoRAにおいて、事前学習済みの重みはどのように扱われますか？」という確認問題が追加された。
  - `make_quiz` の返した問題は「『LoRA』の意味は？」だったが、最終回答では重みの扱いを問う形に言い換えられていた。ツールの出力と最終回答は同じ文章になるとは限らない。
  - 入力／出力トークンは変更前が1346／183、変更後が2454／266だった。この実行では、確認問題の追加に伴ってLLM呼び出し回数とトークン数も増えていた。
  - 変更後の初回実行は503（モデル混雑）で失敗した。同じモデルと質問で変更後だけを再実行して成功し、そのログを比較に用いた。失敗は回答や呼び出し回数が0だったという意味ではなく、成功した比較結果には含めていない。
- 気づき・疑問：
  - 指示を1行変えることで、回答の構成だけでなく、利用するツールとループの回数も変わり得ると分かった。今回の変更後の実行では、確認問題を追加する指示に対応して `make_quiz` が選択された。
  - `--trace` でツール名・引数・返り値・`requests` を確認すると、最終回答だけでは分からない処理を追える。
  - 各条件で成功した実行は1回ずつであり、生成の揺らぎや問題のランダム選択もある。この結果だけで、同じ指示なら必ず同じツールや回数になるとは断定できない。今後は同じ条件で複数回試し、確認問題の内容や呼び出し回数の安定性を調べたい。
- AIツールの利用：Codexによるコード作成・比較手順の準備・実測ログの整理・解答文章の作成支援を受けた。コマンドはCodespacesで実行し、その出力を `results/` に保存した。
